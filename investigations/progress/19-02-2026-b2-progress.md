# B2 Implementation Progress — Inline Exception Match in JIT

**Date:** 19 February 2026
**Author:** claude
**Status:** B2.1 COMMITTED and PUSHED (d4a8e490, ff08db97)

## Summary

Implemented B2: inline exception matching for `try/except SomeType` patterns in the CinderX JIT on aarch64. When a `BINARY_SUBSCR` (dict lookup) occurs inside a try block with a simple handler pattern, the JIT checks the exception type inline and handles the except body directly, without deopting to the interpreter.

B2.1 extends B2 to handle general except bodies (not just `RETURN_CONST`), including loop-body patterns with `LOAD_FAST`, `STORE_FAST`, `BINARY_OP`, and `JUMP_BACKWARD`. This covers the `bench_exceptions` benchmark fully.

## Architecture

### Control Flow (HIR level)

```
                 [try_body_block]
                    CallStatic(PyObject_GetItem)
                    CondBranch(result)
                   /            \
            result OK        result NULL
                |                |
         [ok_block]        [exc_match_block]
          RefineType         Decref excess stack
          (continue)         LoadConst(exc_type)
                             CallStatic(JITRT_MatchAndClearException)
                             CondBranch(match_result)
                            /                    \
                        match                 no match
                          |                      |
                    [match_block]           [deopt_block]
                     (except body            Push left/right back
                      inline)                Deopt(kUnhandledException)
                                             → interpreter exception_unwind
```

### Match Block (B2.1): General Except Body

The match block emits except body bytecodes inline by delegating to existing `emit*` methods:

| Opcode | Handler |
|--------|---------|
| `POP_EXCEPT` | No-op (no exc_info pushed in JIT) |
| `POP_TOP` | Pop stack |
| `LOAD_FAST` | `emitLoadFast(match_tc, ebc)` |
| `LOAD_CONST` | LoadConst + push |
| `STORE_FAST` | `emitStoreFast(match_tc, ebc)` |
| `BINARY_OP` | `emitBinaryOp(cfg, match_tc, ebc)` |
| `RETURN_CONST` | LoadConst + Return |
| `RETURN_VALUE` | Pop + Return |
| `JUMP_BACKWARD` | `Branch(getBlockAtOff(target))` |
| default | Deopt to interpreter |

### Key Design Decisions

1. **CallStatic instead of BinaryOp**: BinaryOp is a `DeoptBase` — the LIR generator automatically emits a deopt guard. By using `CallStatic(PyObject_GetItem)` (not a DeoptBase), we get a raw NULL/non-NULL return and can handle it with explicit `CondBranch`.

2. **Inline except body**: Instead of jumping to a separately-translated block (via `getBlockAtOff` + `pending_b2_blocks_`), we emit the except body inline. This avoids register allocation conflicts where the exc_match_block clobbers registers that the except_body_block expects to be live.

3. **TCInt32 for match result**: `JITRT_MatchAndClearException` returns `int`. Using `CallStatic` with `TCInt32` return type prevents the generated code from trying to Decref the integer return value as a PyObject*.

4. **No-match deopt with left/right re-pushed**: The no-match deopt pushes `left` and `right` back onto the stack (they were popped by `emitBinaryOp`), then deopts at `bc_instr.baseOffset()`. The Deopt instruction uses `kUnhandledException` reason, which sets `throwflag=1`. The interpreter enters `exception_unwind`, walks `co_exceptiontable`, and finds the correct handler — including outer handlers for nested try blocks.

5. **JITRT_MatchAndClearException restores on no-match**: On match, the exception is consumed (Decref'd) and the function returns 1. On no-match, the exception is restored via `PyErr_SetRaisedException(exc)` and the function returns 0. The deopt uses `kUnhandledException` which causes the interpreter to enter `exception_unwind` with the exception still pending — no re-execution of BINARY_SUBSCR needed.

## Bugs Fixed During Implementation

| Bug | Root Cause | Fix |
|-----|------------|-----|
| Decref of int value (SIGSEGV at x21=1) | `CallCFunc` returns `TOptObject\|TCUInt64`, code tried to Decref the match_result integer | Use `CallStatic` with `TCInt32` return type |
| Register allocation conflict (SIGSEGV) | `CondBranch` to separately-translated `except_body_block` — exc_match_block clobbers registers expected by except_body | Emit except body inline in the match_block instead |
| Deopt crash on no-match (PyTraceBack_Here) | Deopt at `handler.target` with `exc_tc.frame` — exception state threading not set up for PUSH_EXC_INFO | Use `bc_instr.baseOffset()` with left/right pushed back |
| Exception state leak (sys.exc_info not cleared) | Original deopt at `bc_instr.baseOffset()` without left/right — stack corruption because emitBinaryOp already popped them | Push left/right back onto deopt stack before snapshot |
| Nested try/except skips outer handler | Return(nullptr) on no-match bypasses outer try/except blocks in same function | Use Deopt(kUnhandledException) instead, letting interpreter find correct handler |

## Benchmark

### B2.0 (simple return pattern only)
- **Vanilla CPython:** median = 0.0602s
- **B2 JIT:** median = 0.0584s
- **Improvement:** ~3%

### B2.1 (general except body — loop continuation)

| Scenario | Time (2M iterations) | Deopts |
|----------|---------------------|--------|
| Mostly hits (no exceptions) | 0.1196s | 0 |
| 50% miss (frequent exceptions) | 0.1593s | **0** |

The 50% miss case previously had 1 deopt (falling back to interpreter on first exception). Now with B2.1, the entire exception handling stays in the JIT — zero deopts even with frequent exceptions.
